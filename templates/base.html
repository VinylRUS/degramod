v4.7.7 — 1 августа 2026

  • Хотфикс toggle-кнопок: при пустых полях даты в форме добавления sanitary-периода браузерная HTML5-валидация блокировала сабмит ВСЕХ toggle-кнопок (SAN / NIGHT / CAS / LINK / ENABLE / REPORT), потому что они жили в той же форме с required-полями и использовали formaction. Симптом: при нажатии SAN появлялось сообщение «Вы пропустили это поле» под Start date, переключение не происходило.
  • Решение: ко всем toggle-кнопкам и кнопкам удаления sanitary-периодов добавлен атрибут formnovalidate — браузер пропускает HTML5-валидацию при сабмите через formaction. Серверная валидация в add_sanitary_period и delete_sanitary_period остаётся полной. Кнопка «Сохранить» валидирует форму как и раньше — все её поля валидны по построению.
  • Сохранена работоспособность: toggle-кнопки снова кликаются из любого состояния карточки (с пустыми или заполненными полями sanitary-формы). Кнопка «+ Add» по-прежнему требует заполнения start_date и end_date — но уже через серверную валидацию, а не через блокирующий browser tooltip.

v4.7.6 — 1 августа 2026

  • UI санитарных дней в карточке чата: вместо textarea теперь удобный date/time picker. Четыре поля (start date / start time / end date / end time) + кнопка «+ Add» — добавляет период одним кликом. Время опционально — если оставить пустым, период full-day (старое поведение). Список назначенных периодов отображается ниже с кнопкой «✕» для удаления каждого. Старый textarea спрятан под <details> Raw JSON (advanced) — для совместимости с bot-командами и ручного редактирования.
  • Поддержка времени в sanitary-периодах: формат JSON расширен — каждая запись теперь может содержать опциональные start_time и end_time (HH:MM). Tick-логика (_sanitary_day_tick) проверяет периоды со временем через datetime-сравнение (с учётом TZ чата), без времени — через date-сравнение (старое поведение). Пример: ["2026-07-31","2026-08-03","23:00","09:00"] = санитарные дни с 23:00 31 июля по 09:00 3 августа.
  • Упразднена система private/non-private чатов: toggle «🔒 PRIVATE / 🔓 PUBLIC» убран из карточки чата. Колонка is_private в БД сохранена для совместимости, но больше не используется в логике доступа — admin теперь имеет доступ во все чаты (как и SU, но без права удаления). Badge «PRIVATE» убран из заголовка карточки.
  • Перенос тогглеров NIGHT/SAN в action buttons: toggle включения ночного режима и санитарных дней перенесён из <details> секций в зону компактных action-кнопок (где CAS/LINK/REPORT). Теперь все 6 toggle-кнопок (Enable / CAS / LINK / NIGHT / SAN / REPORT) в одном ряду.
  • Перенос Sync admins в action buttons: кнопка «↻ Sync» (только для SU) перенесена из <details> Общее в зону action buttons (между «Настроить» и «Удалить»). Лейбл сокращён с «↻ Sync admins from TG» до «↻ Sync».
  • Компактные лейблы кнопок: «LINK-FILT» → «LINK», «make report» → «REPORT». Кнопки остались того же размера — сокращён только текст внутри.
  • Новые backend handlers: POST /admin/chats/{id}/sanitary/add и POST /admin/chats/{id}/sanitary/{idx}/delete для управления периодами без полного ресайза textarea.

v4.7.4 — 1 августа 2026

  • Хотфикс: сохранение настроек чата не работало. В шаблоне /admin/chats главная форма <form action="/admin/chats/{id}/update"> содержала ВНУТРИ себя несколько других <form> для inline toggle-кнопок (Enabled/CAS/Link-filter/Private/Make report + sync-admins + night_mode toggle + sanitary_days toggle). HTML запрещает вложённые <form> — браузер при парсинге автоматически закрывает внешнюю форму перед первой вложенной. В итоге /update форма реально содержала только поля ДО первого toggle (никаких), и при нажатии «Сохранить» сабмитилась пустая форма. Все поля (hashtag, warns_to_mute, night_mode_start, sanitary_days_text и т.д.) оказывались вне формы и не отправлялись.
  • Решение: inline toggle <form> заменены на <button type="submit" formaction="/admin/chats/{id}/toggle" formmethod="post" name="field" value="...">. Кнопка остаётся внутри главной /update формы, но formaction переопределяет action родительской формы при submit — POST уходит на /toggle, а не на /update. Это стандартный HTML5-механизм, поддерживается всеми браузерами с 2014 года.
  • Toggle-кнопки работают как раньше: мгновенный POST без необходимости жать «Сохранить». Visual layout не изменился — кнопки остались в тех же секциях <details>.
  • Добавлены тесты: test_v474_update_form_fix.py (7 E2E тестов через TestClient — POST на /update реально сохраняет hashtag/warns_to_mute/etc в БД) + test_v473_nested_forms_bug.py (2 static-теста — в шаблоне нет вложённых <form>, поле hashtag внутри update-формы).

v4.7.3 — 1 августа 2026

  • Единый asyncio.TaskGroup для всех background loops: раньше ночной режим и long polling запускались через asyncio.create_task и «забывались». При SIGTERM процесс обрывался, не дожидаясь завершения тика night mode — это могло оставить чат в состоянии night_mode_currently_active=True с зависшим флагом. Теперь все loops живут в одном TaskGroup, shutdown отменяет их и ждёт завершения с hard timeout 5 секунд.
  • Startup recovery: при старте бот проверяет все чаты с зависшими night_mode_currently_active=True или sanitary_days_currently_active=True (после жёсткого SIGTERM в предыдущем запуске) и прогоняет один немедленный tick — восстанавливает права из snapshot в БД, если режим уже вышел из окна. Snapshot лежит в night_mode_saved_permissions / sanitary_days_saved_permissions в БД, так что recovery всегда возможен.
  • asyncio.Semaphore(100) для ephemeral auto-delete: каждое ephemeral-сообщение (уведомление модератору, варн-уведомление нарушителю, fallback-ответ в чат) порождает fire-and-forget корутину sleep(N) → delete_message. Раньше таких корутин создавалось без ограничений — поток из 1000 варнов за минуту породил бы 1000 спящих задач. Теперь Semaphore(100) ограничивает количество одновременно ожидающих auto-delete-задач: 101-я ждёт освобождения слота.
  • Hard shutdown timeout 5 секунд: если background task игнорирует CancelledError и не успевает завершиться за 5 секунд — бот логирует список всё ещё работающих задач и выходит принудительно. Event loop закроется, задачи умрут.

v4.7.2 — 1 августа 2026

  • Явный toggle для ночного режима и санитарных дней: раньше ночной режим включался автоматически при задании start/end, санитарные дни — при добавлении дат. Теперь оба требуют явного включения через кнопку 🌙 Night mode ● ENABLED / 🧹 Sanitary days ● ENABLED в соответствующей секции /admin/chats. Настройки сохраняются при выключении, но бот не применяет ограничения пока toggle off.
  • Подавление варнингов: для чатов с выключенным ночным режимом / санитарными днями бот больше не генерирует логи logger.warning и не показывает UI-бейджи. Команды /nightmode и /sanitary отвечают «функция выключена, сначала включите» при попытке add/toggle/notify на выключенном режиме.
  • Новые подкоманды on/off: /nightmode chat_id on, /sanitary chat_id on, /sanitary chat_id off — явный toggle через CLI. Команда off корректно выходит из активного состояния (восстанавливает права из snapshot), не оставляя чат в night/sanitary-правах.
  • Миграция: при первом запуске v4.7.2 все существующие night_mode_enabled и sanitary_days_currently_active сбрасываются в False. После обновления SU должен явно включить функции в нужных чатах через /admin/chats. Это сознательное решение — пользователь предпочёл чистый старт для toggles.
  • Скрытие бейджа SAN: в карточке чата бейдж SAN показывается только если sanitary_days_enabled=True И есть даты. Раньше показывался при наличии дат даже если функция по факту не активна.

v4.7.0 — 1 августа 2026

  • Авто-обнаружение админов чата: ручное создание пользователей в /admin/users упразднено. Теперь SU жмёт кнопку «↻ Sync admins from TG» в карточке чата (страница /admin/chats) → бот получает список TG-админов через get_chat_administrators и создаёт для каждого pending-учётку (is_active=False, без пароля).
  • Активация через /start: юзер, которого SU синхронизировал, пишет боту /start в ЛС → бот генерирует пароль, активирует учётку (is_active=True, is_pending=False), скачивает аватарку и шлёт DM с логином/паролем под спойлером. Посторонним бот по-прежнему молчит (стелс).
  • Роль по TG-правам: если у админа есть can_promote_members (=owner) → роль admin, иначе moderator (привязан к своему чату через chat_admins). Логин: @username или tg<TGID> если @username нет.
  • Demote = deactivate: при следующем sync, если TG-owner снял админа в чате, его WebUser-moderator деактивируется (is_active=False). SU может реактивировать вручную.
  • Репорт-чат минимализм: при is_report_chat=True в карточке чата скрыты все настройки кроме enabled и ★ REPORT. Репорт-чат не модерируется — нет смысла настраивать CAS/link-filter/night/sanitary. Sync admins для репорт-чатов тоже недоступен.
  • pending-бейдж в /admin/users: pending-юзеры (не написали /start) показываются с жёлтым бейджем PENDING. Авто-созданные учётки помечены серым auto. SU может: деактивировать, сменить роль, сбросить пароль, удалить, привязать другой TG ID.

v4.6.0 — 30 июля 2026

  • Гранулярные права: теперь можно явно задавать права чата для дневного, ночного и санитарного режимов через пресеты. Больше не нужно полагаться на snapshot текущих прав — задайте свой набор в /admin/presets и привяжите к чату.
