# План/итог: CAS+LOLS ночные проверки сидящих (v5.3.2)

> 2026-08-30. Автор: Пупсик (агент VinylRUS, AutoClaw) по запросу владельца.
> Документ для второго разработчика и его нейронки: что сделано, почему так,
> как проверить, что осознанно НЕ сделано.

## Контекст

CAS (v4.5.2) проверял по api.cas.chat только **входящих** участников.
Спамер, который зашёл раньше включения CAS или сидит давно, никогда не
проверялся. Задача (issue #10 соседней линии, предложение владельца
29.08.2026): проверять уже сидящих.

## Жёсткое ограничение, из которого вырос весь дизайн

**Telegram Bot API не умеет перечислять участников чата.** Нет эндпоинта
«дай всех members»; `getChatAdministrators` — только админы. Люркеров,
никогда не писавших, бот не увидит никак. Решение: «сидящие» = те, кто
писал (таблица `chat_members_seen`, наполняется middleware на каждом
сообщении в CAS-чатах). Спамер безвреден, пока молчит — первое же его
сообщение попадает в проверку.

## Что сделано (v5.3.2)

### 1. TTL reply_contexts 30 → 7 дней
`_REPLY_CONTEXT_TTL_DAYS` в bot_handlers.py. Причина: reply_contexts
растёт на ~5400 строк и ~1.5 МБ в сутки (21 958 строк / ~6 МБ за четверо
суток после выката v5.2.0). После деплоя: разово
`_purge_reply_contexts(7)` + VACUUM в /admin/settings.

### 2. Ночной CAS/LOLS-свип (cas.py, NEW)
- **Окно 01:00–05:00 МСК**, днём ноль запросов к внешним API (решение
  владельца: RPS-сомнения + санитарный день как усиленный режим).
- **01:00 МСК** — bulk-лист LOLS: `GET lols.bot/scammers.json`
  (~1 МБ, 10 864 user_id на 29.08.2026) → in-memory Set. Один запрос
  в сутки; LOLS-вердикты дальше мгновенно из памяти.
- **01:10 МСК** — свип по `chat_members_seen` (last_seen ≤ 90 дней,
  env `CAS_SWEEP_SEEN_DAYS`): CAS per-id (`api.cas.chat/v1/status`,
  ≤5 rps, fail-open, 3 с таймаут), LOLS — из памяти. Найденные →
  автобан (`tg_safe_call` + `_mark_bot_ban` + `_save_punishment`,
  mod_id=0 «CAS System»).
- **Вердикт юзера = CAS banned OR LOLS banned.** У LOLS в API есть
  `offenses` и `spam_factor` (гибче CAS) — порог заложен на будущее,
  v1 банит по `banned=true`.
- **Кэш `cas_verdicts`**: один юзер = один внешний запрос в 30 дней.
- **Санитарный день**: свип при включении + каждый час (усиленный
  режим), LOLS-лист освежается при простоях > 6 ч.
- **05:00 МСК** — дайджест в репорт-чат, ровно одна строка:
  «🛡️ CAS/LOLS за сутки: проверено N, забанено M (id: …)». Это и
  живой индикатор: нет строки в 05:00 — ночной свип умер.
- **cas_ignore**: разбан CAS-бана (revoke_user_ban — единая точка для
  !unban и веб-панели) автоматически добавляет юзера в whitelist —
  повторного автобана не будет.

### 3. Middleware MembersSeenMiddleware
Вешается на router.message из cas.py (bot.py импортирует cas после
bot_handlers — роутер уже собран, aiogram применяет динамически).
Пишет last_seen только для чатов с включённым CAS; для остальных —
passthrough. Это НЕ CAS-запрос — локальный SQLite upsert.

## Что осознанно НЕ сделано
- **Двухфазные подтверждения** — владелец просил минимум ручного ввода:
  ночной свип банит сразу, откат через cas_ignore (разбан → авто-whitelist).
- **Inline CAS-проверка авторов сообщений днём** — заменена ночным окном.
- **Создание issues под стримбот/TOTP/staging** — ждёт обсуждения с
  модераторами и стримером (решение владельца 29.08.2026).
- **Env-конфиг расписания** — 01:00–05:00 МСК захардкожено, выносится
  по запросу.

## Как проверить
1. Включить CAS у чата в панели (кнопка CAS в /admin/chats).
2. Пусть в чате кто-то напишет (или написать самому) → появится строка
   в `chat_members_seen`.
3. Дождаться ночного окна (или вызвать `_nightly_sweep_all(bot)` вручную).
4. Спамеры из CAS/LOLS забанены; в 05:00 МСК в репорт-чате дайджест.
5. Ложное срабатывание → разбан → юзер в `cas_ignore` → свип его пропускает.

## Открытый вопрос
Порог LOLS: v1 банит по `banned=true`. Если будут ложные срабатывания —
включить порог по `spam_factor`/`offenses` (поля уже в API и в кэше).
